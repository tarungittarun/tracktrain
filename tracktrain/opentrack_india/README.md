# OpenTrack India 🚆

**Production-ready, offline-first Android railway tracking.**
Bundled SQLite timetable · GPS + cell-tower dual tracking · destination wake-up alarms · 100% on-device analytics.

> Zero paid API keys · zero third-party proxy dependency · zero ads · zero telemetry.
> Everything runs on the phone — the app is fully functional in airplane mode.

---

## Feature map

| Spec area | Implementation |
|---|---|
| **Dual offline tracking engine** | `LocationTrackerService` (GPS, adaptive polling) + `CellInfoService` → native `TelephonyManager` channel → `CellTowerRepository` matching MCC/MNC/LAC/CID against the bundled OpenCelliD-style table |
| **Live speedometer** | Exponentially-smoothed `geolocator` velocity rendered by a dependency-free analog+digital `CustomPainter` gauge (km/h or mph) |
| **Destination alarm** | 5 km / 10 km lead; two layers — exact `zonedSchedule` (AlarmManager, survives doze) + proximity fire with full-screen intent; kept alive by a location-typed Android 14/15 foreground service |
| **Offline timetable & typo-tolerant search** | Bundled SQLite DB with **FTS5** prefix matching (stations incl. vernacular `name_local`, trains) + Dart-side Levenshtein re-rank; automatic LIKE fallback on devices without FTS5 |
| **Live hybrid fallback** | `LiveRailService` — optional user-configured JSON endpoint; any failure (timeout, DNS, bad JSON, empty config) transparently falls back to the offline schedule |
| **On-device analytics dashboard** | Hive boxes only: screen time, session count, offline/online split, km tracked, average/top speed, travel hours, **data-saved counter**, weekly bar chart, swipe-to-delete trip log |
| **IST + GPS clock correction** | All math locked to `Asia/Kolkata` via `timezone`; satellite timestamps drive an EMA clock-skew estimator that fixes manually-altered device clocks |
| **Localization** | `intl`/`.arb` via `flutter gen-l10n`: English, Hindi, Bengali, Telugu, Tamil, Marathi, Kannada, Gujarati |
| **Themes** | Material 3 Light / Dark / **OLED pure-black** + high-contrast outdoor mode (boosted weights + 1.15× type scale) |
| **Battery** | GPS distance filter adapts: 40 m stationary → 15 m rolling → 5 m above 40 km/h |
| **Release build** | R8 `isMinifyEnabled = true`, `isShrinkResources = true`, ProGuard rules committed |

## Tech stack

Flutter (Dart) · `flutter_riverpod` · `sqflite` (FTS5) · `hive`/`hive_flutter` · `geolocator` · `flutter_local_notifications` · `connectivity_plus` · `permission_handler` · `intl` — targeting **Android API 24–36** (Android 7.0 → 15+).

Cell-tower reads are implemented natively in `MainActivity.kt` (own `MethodChannel`) instead of an unmaintained third-party plugin — guarded per API level (GSM/LTE/WCDMA/NR), degrading to an empty list instead of crashing.

## Bundled datasets (sample → production)

`assets/data/` ships a **representative sample** (43 major stations with
vernacular names, 8 trains with full routes, 10 cell towers) so the app is
usable immediately. To load the full Indian Railways catalogue
(~8,500 stations / ~12,000 trains):

1. Replace the CSVs keeping the exact headers:
   - `stations.csv` → `code,name,name_local,city,state,lat,lon`
   - `trains.csv` → `number,name,src,dst,days,type` (`days` = `1111111` Mon→Sun)
   - `train_stops.csv` → `train_number,seq,station_code,arrival,departure,distance_km,day_offset`
   - `cell_towers.csv` → `mcc,mnc,lac,cid,lat,lon,station_code,accuracy_m`
2. Uninstall/reinstall (or bump the DB version) — the DB is created & seeded on first launch.

## Live-data endpoint contract (optional Internet Mode)

Settings → *Live data endpoint* accepts any base URL that implements:

```
GET {base}/train/{trainNumber}/status
200 → { "delay_minutes": 15, "platform": "4" }
```

Leave it empty for a purely offline app. All failures degrade gracefully to the bundled schedule.

## Build locally

```bash
flutter pub get
flutter gen-l10n
flutter analyze
flutter test
flutter build apk --release        # → build/app/outputs/flutter-apk/app-release.apk
```

Requirements: Flutter stable, JDK 17, Android SDK with platform 36 + build-tools.

## Build the APK with GitHub Actions (recommended)

The workflow `.github/workflows/build-apk.yml` runs on every push/PR:
setup-java 17 → Flutter stable → `pub get` → `gen-l10n` → `flutter analyze` →
`flutter test` → `flutter build apk --release --split-per-abi` (R8 minified +
resource-shrunk) → uploads three APKs as artifacts:

| Artifact | Covers | Size |
|---|---|---|
| `OpenTrackIndia-v<ver>-arm64-v8a.apk` | every modern phone (install this one) | ~10 MB |
| `OpenTrackIndia-v<ver>-armeabi-v7a.apk` | very old 32-bit devices | ~9 MB |
| `OpenTrackIndia-v<ver>-x86_64.apk` | emulators / Chromebooks | ~11 MB |

Pushing a tag `v*` additionally creates a **GitHub Release with all APKs attached**.

```bash
# 1. push the project
git init
git add -A
git commit -m "OpenTrack India: offline-first railway tracking"
git branch -M main
git remote add origin https://github.com/<you>/opentrack-india.git
git push -u origin main

# 2. grab the APK
#    GitHub → repo → Actions → "Build OpenTrack APK" → Artifacts
#    …or tag a release:
git tag v1.0.0 && git push origin v1.0.0   # → Releases tab with APK attached
```

The CI APK is signed with the debug keystore for instant installability.
For Play Store distribution, create a keystore, add a
`key.properties` (gitignored) and point the release `signingConfig` at it.

## Privacy & permissions

| Permission | Why |
|---|---|
| Fine/coarse location | GPS mode of the tracking engine |
| Foreground service (location) | Screen-off journey tracking (Android 14/15 typed FGS) |
| Post notifications + exact alarms | Destination wake-up alarm |
| Internet / network state | Optional live mode only; the app works fully without |

No analytics SDK, no crash reporter, no ad SDK — the usage dashboard is
explicitly local-only (see the banner on the Dashboard tab).

## Known trade-offs

- Remaining-distance ETA uses great-circle × 1.2 rail factor when no route
  geometry is bundled; swap in per-route polylines in `tracking_controller.dart`
  for survey-grade projection.
- Cell Tower Mode accuracy equals the density of the bundled tower table.
- Sample timetable ≠ live IRCTC data; plug the live endpoint for delay feeds.
